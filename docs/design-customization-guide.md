# Oni Chat Overlay Graphics and Design Customization Guide

This guide describes how to change the visual identity of the restored `c33204f9` baseline without breaking the Twitch relay, OBS URL generation, or transparent overlay behavior. The design is intentionally code-driven: the browser UI is the source of truth, and OBS receives the `/overlay?...` URL generated by the control room.

## Design map

| Visual area | Primary file | What to change |
|---|---|---|
| Shared theme names, defaults, and URL-safe configuration | `shared/chat.ts` | Add or rename themes, accents, defaults, animation names, and allowed values. |
| Control room layout and global visual system | `client/src/index.css` | Colors, typography, spacing, panels, responsive breakpoints, scanlines, buttons, and preview stage. |
| Control-room content and configuration fields | `client/src/pages/Home.tsx` | Headline, explanatory copy, labels, settings controls, and preview switcher. |
| Transparent OBS overlay shell | `client/src/pages/OverlayPage.tsx` | Overlay structure, message stack, status display, and CSS theme classes. |
| Live/demo message visual treatment | `client/src/components/overlay/ChatMessage.tsx` | Message card, badges, usernames, timestamps, emotes, cheers, subscriptions, and raids. |
| In-page OBS preview | `client/src/components/overlay/OverlayPreview.tsx` | Checkerboard transparency stage, landscape/vertical canvas, and preview scaling. |
| Demo content | `client/src/lib/demoMessages.ts` | Safe local examples used only when demo mode is enabled. |
| URL serialization and validation | `client/src/lib/overlayConfig.ts` | Query-string names, numeric limits, booleans, and allowed visual values. |
| Design tests | `client/src/lib/overlayConfig.test.ts` | Update when adding configuration fields or allowed values. |

## Changing the palette

The most direct design edits are in `client/src/index.css`. The baseline uses dark navy backgrounds, electric cyan lines, hot magenta accents, and restrained blue-gray body text. Search for selectors such as `.control-room`, `.settings-panel`, `.overlay-shell`, `.message-body`, `.message-name`, `.message-text`, `.preview-frame`, and `.signal-card`.

A theme is applied by the class `theme-oni`, `theme-minimal`, or `theme-matrix` on the overlay root. Accent classes are `accent-magenta`, `accent-cyan`, and `accent-red`. Each theme or accent changes CSS custom properties on `.overlay-shell`, for example:

```css
.overlay-shell.theme-oni {
  --pink: #ff4fba;
  --cyan: #57e6ff;
}

.overlay-shell.theme-minimal {
  --pink: #d9e7ff;
  --cyan: #a4b7d6;
}
```

To add a new theme, add the class in CSS, add its name to `ALLOWED_THEMES` in `shared/chat.ts`, and add an option in the theme `<select>` inside `Home.tsx`. Keep the class name lowercase and URL-safe. Do not accept arbitrary CSS values from query parameters.

## Changing typography

The font imports and global type system are defined near the top of `client/index.html` and `client/src/index.css`. The baseline uses a condensed display face for labels and headlines and a readable sans-serif face for body text. To change the display typography, update the `font-family` declarations on `h1`, `.panel-heading`, `.eyebrow`, `.url-block span`, `.signal-card`, and `footer`. To change message typography, update `.message-meta` and `.message-text`.

The user-facing **FONT SIZE** field changes the `fontSize` query parameter. Its safe range is currently 12–42 pixels. The **CHAT WIDTH** field changes `width`, currently limited to 240–1000 pixels. Change these limits only together in `Home.tsx`, `shared/chat.ts`, and `client/src/lib/overlayConfig.ts`; otherwise the control room and URL parser can disagree.

## Changing the overlay message design

`client/src/components/overlay/ChatMessage.tsx` controls each visible chat message. The main selectors in `index.css` are:

| Selector | Purpose |
|---|---|
| `.chat-message` | Entrance and exit motion for a message. |
| `.message-rail` | Neon vertical signal rail. |
| `.message-body` | Transparent dark message backing and padding. |
| `.message-meta` | Username, timestamp, and event labels. |
| `.message-text` | Chat message text and wrapping behavior. |
| `.chat-badge` | Subscriber, moderator, VIP, and bits badge presentation. |
| `.chat-emote` | Twitch emote sizing and alignment. |
| `.system-subscription`, `.system-raid` | Special event colors and backgrounds. |
| `.is-compact` | Reduced-padding compact mode. |

Preserve `overflow-wrap: anywhere` on `.message-text`, because long usernames, URLs, and unbroken text must not create horizontal overflow in OBS.

## Adding graphics and image assets

The overlay is designed to stay lightweight and transparent. For small static graphics such as a logo, badge, or corner mark, place the source asset outside the project in `/home/ubuntu/webdev-static-assets/`, upload it using the project asset workflow, and reference the returned durable storage URL. Do not place large images, videos, or font files in `client/public/` or `client/src/assets/`; those can slow or break deployment.

For CSS-only atmosphere, prefer gradients, borders, shadows, scanlines, and masks in `index.css`. This keeps the OBS Browser Source transparent and avoids adding an opaque image rectangle behind chat. If you add an image to the overlay, use `pointer-events: none`, preserve `alt` handling when meaningful, and ensure it does not cover chat or interfere with the checkerboard preview.

## Editing the control room

`client/src/pages/Home.tsx` contains the control-room copy and fields. The visible in-page OBS preview is rendered by `OverlayPreview` and supports both **16:9 LANDSCAPE** and **9:16 VERTICAL** canvases. When adding a new visual control, keep this sequence consistent:

1. Add the field to `OverlayConfig` in `shared/chat.ts`.
2. Add URL parsing and bounds in `client/src/lib/overlayConfig.ts`.
3. Add URL serialization in the same file.
4. Add a control to `Home.tsx`.
5. Apply the value in `OverlayPage.tsx`, `OverlayPreview.tsx`, or CSS.
6. Add or update a Vitest case in `client/src/lib/overlayConfig.test.ts`.

Never make the control room and overlay use separate, duplicated configuration objects. The generated URL must remain the single handoff between the control room and OBS.

## Responsive layout rules

The restored baseline contains the original responsive improvement in `index.css`. The important breakpoints are approximately 900 pixels and 560 pixels. The first collapses the two-column control room into a vertical layout; the second makes form rows single-column and reduces preview padding. When adjusting widths, use `minmax(0, 1fr)`, `min-width: 0`, `max-width: 100%`, and `overflow-wrap: anywhere` to prevent narrow browser windows from growing horizontally.

For OBS, set the Browser Source width and height to the actual canvas size, enable **Shutdown source when not visible** only if you accept reconnect behavior, and keep the generated URL unchanged. Use the control-room preview before changing CSS in production.

## Safe local workflow

Run the following after a design change:

```bash
pnpm check
pnpm test -- --run
pnpm build
```

Then verify at least these viewport sizes in the preview: 1280×720 desktop, 768×1024 tablet, 375×812 mobile, and 1920×1080 OBS landscape. Also test a 1080×1920 vertical canvas when changing preview or mobile-specific rules.

Use demo mode to check visual changes without Twitch credentials:

```text
/overlay?demo=true&theme=oni&accent=magenta&fontSize=18&width=520
```

Do not commit credentials, access tokens, `.env` files, or generated private deployment archives. Keep server-side Twitch credentials and tenant token encryption untouched while editing design files.

## Design checklist

Before saving a design checkpoint, confirm that the overlay remains transparent outside message content, text remains readable against every theme, messages wrap without horizontal overflow, reduced-motion preferences still work, both preview orientations render, the generated OBS URL still updates, and all tests/build checks pass.
